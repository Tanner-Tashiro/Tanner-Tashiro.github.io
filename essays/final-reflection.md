When I first started this course, I tended to think of software engineering mainly as “building web applications.” While I did learn how to design and implement web apps, I now see that the underlying lessons were about how to build software in a maintainable and collaborative way. In particular, three ideas stand out as being broadly useful beyond web development: Agile project management (especially Issue-Driven Project Management), configuration management, and design patterns. These concepts can be applied to almost any software project and is key points of understanding concepts in software engineering

## Agile Project Management and Issue-Driven Project Management

Agile project management is a way of organizing work that emphasizes flexibility, iteration, and continuous feedback. Instead of trying to plan an entire project in detail from the beginning and then executing it in one long phase, we can break work into smaller tasks and cycles. After each cycle, the team reviews progress and adjusts plans based on what they learned. This makes it easier to respond to changing requirements or unexpected problems.

A specific version of this approach that we used in class is Issue-Driven Project Management. In IDPM, work is organized around “issues,” which are concrete tasks, bugs, or feature requests that need to be resolved. Each issue is tracked, assigned, worked on, and closed when completed. The emphasis is on continuous progress tracking and communication among team members. What I found important about this approach is that it is not limited to software. I could use IDPM in a various other classes not related to ICS, where issues might include stuff like “collect sources for background research,” “analyze dataset,” or “draft report section.” Even in a non-technical workplace project, breaking work into issues and tracking them publicly would help prevent confusion, duplicated effort, and missed tasks. Agile methods in general are useful anywhere requirements evolve or are not fully known at the start.

## Configuration Management

Configuration management refers to the process of tracking and controlling changes to a software system over time. This includes managing source code, documentation, dependencies, and different versions of a project. Tools like GitHub allow developers to see who changed what, when changes were made, and why. They also make it possible to safely collaborate, because multiple people can work on the same project without overwriting each other’s work. This is one of those topics that was most challenging for our final project group. Since it was everyone's first time working as a group we often struggled with merging branches into main since often times the brances would be outdated or we would interfere with each others work.

Beyond web development, configuration management is essential in any collaborative technical project. For example, in data science, teams often manage evolving scripts, datasets, and model configurations. In hardware-related projects, configuration management could include tracking firmware versions or design files. Even in academic writing projects with multiple contributors, version control can prevent lost work and confusion over edits. The key idea is that as soon as a project involves more than one person or more than one version of itself; configuration management becomes critical for maintaining order and accountability.

## Design Patterns

A design pattern is a general, reusable solution to a common problem in software design. It is not a finished piece of code, but rather a template or strategy for solving a recurring type of problem. For example, some patterns focus on how objects are created, others focus on how components communicate, and others help structure large systems so they are easier to understand and modify.

What makes design patterns valuable beyond web applications is that they represent transferable thinking. Instead of solving the same problem from scratch every time, developers can recognize patterns and apply proven solutions. For instance, the idea of separating concerns; keeping different parts of a system responsible for different tasks, can be applied in desktop applications, game development, or even organizational workflows. In a non-software context, similar “pattern thinking” appears when teams standardize how they handle recurring problems, such as approval processes or communication structures. Learning design patterns has helped me think more in terms of structure and long-term maintainability rather than just immediate functionality.

## Conclusion

Overall, this course taught me that software engineering is more about a set of principles for building and maintaining complex systems. Agile project management (especially Issue-Driven Project Management) provides a way to organize work and adapt to change. Configuration management ensures that changes are controlled and collaboration is possible. Design patterns encourage reusable, structured solutions to common problems. Together, these ideas apply far beyond web development and can be used in many kinds of projects where people need to build something complex, coordinate effectively, and adapt over time.
